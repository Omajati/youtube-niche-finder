# YouTube Niche Finder

Ищет перспективные ниши для длинных роликов (от 8 минут) на YouTube: где малые каналы
набирают просмотров кратно больше, чем у них подписчиков, новые каналы быстро растут,
а миллионников почти нет. Рынки: английский, испанский, немецкий, французский и русский.
У русского рынка RPM по умолчанию низкий: монетизация YouTube в России отключена, доход обычно с интеграций.

## Приложение для Mac (проще всего)

1. Скачайте [NicheFinder.zip](https://raw.githubusercontent.com/Omajati/youtube-niche-finder/main/release/NicheFinder.zip).
   Двойной щелчок распакует архив.
2. Перетащите «Поиск ниш» в папку «Программы» и запустите.
3. Первый раз Mac скажет, что не может проверить разработчика: нажмите «Готово», откройте Системные настройки →
   Конфиденциальность и безопасность и внизу нажмите «Всё равно открыть».
4. При первом запуске программа сама доустановит всё нужное (1–2 минуты) и откроет своё окно.
5. Впишите ключи YouTube API в окне «Настройки» (оно откроется само, если ключей нет).

Когда выходит новая версия, вверху появляется зелёная кнопка «Обновить». Ключи, результаты и кэш сохраняются.

Где что лежит: программа в `~/NicheFinder`, ключи и результаты в `~/NicheFinder/data`.

### Как выпустить новую версию

Поднимите число в `VERSION`, затем `bash mac/release.sh "что нового"`, закоммитьте и запушьте в `main`.

## Через GitHub Desktop (для разработки)

1. Установите [GitHub Desktop](https://desktop.github.com/) и войдите в свой аккаунт GitHub.
2. File → Clone repository → `youtube-niche-finder` → Clone. Папка появится в `Documents/GitHub`.
3. Дважды кликните `start.command` в этой папке. В первый раз создастся `.env` и откроется
   в TextEdit: впишите ключи, сохраните и снова кликните `start.command`.

Дальше просто запускайте `start.command`: он сам подтягивает свежую версию и открывает дашборд.
Если `git pull` не сработает, нажмите в GitHub Desktop кнопку **Fetch origin → Pull origin**.
Ключи (`.env`) и результаты (`data/`) при обновлении не трогаются.

Если Mac пишет, что файл от неизвестного разработчика: правый клик по `start.command` → Открыть → Открыть.

## Запуск вручную

Нужен только Python 3.9+, внешние библиотеки не требуются.

1. Скопируйте `.env.example` в `.env` и впишите ключи YouTube Data API v3 в `YOUTUBE_API_KEYS`
   (до 4 штук через запятую). Файл `.env` не попадает в git.
2. Запустите дашборд:
   ```
   python app.py
   ```
   Откроется http://localhost:8766. Слева впишите темы и языки и нажмите «Запустить анализ».

Можно и из командной строки:
```
python cli.py "unsolved mysteries" --langs en --expand 3 --max 8
python cli.py --langs es --expand 2      # автопоиск от стартовых тем
```

### Как получить ключ

Google Cloud Console → новый проект → APIs & Services → Library → «YouTube Data API v3» → Enable →
Credentials → Create credentials → API key. Повторите в каждом Google-аккаунте.

## Автопоиск: машина по подбору ниши

Тему задавать не нужно. Вкладка «Автопоиск» сама перебирает каталог из 25 вечнозелёных категорий
(загадки, древние цивилизации, быт в прошлом, мифология, космос, психология, история изобретений,
истории для сна и т.д., файл `niche_finder/catalog.py`).

1. **Разведка** (≈102 единицы на тему): один поиск и статистика. Около 60% бюджета запуска.
   Берутся категории, которые разведывали реже всего, их стартовые запросы и подсказки YouTube.
2. **Полный анализ** лучших по разведке (≈144 единицы сверху): второй поиск и последние ролики малых каналов.
3. **Подниши** хороших ниш (балл от 50: подсказки YouTube и теги успешных роликов) уходят в очередь.
   Следующий запуск разведывает их первыми, так что каждый запуск уходит глубже в удачные темы.

Очередь и пройденные категории хранятся в `data/autopilot.json`. Бюджет запуска задаётся на дашборде
(3000 единиц ≈ 17 тем на разведку и 8 на полный анализ).

### Откуда автопоиск берёт темы

- **Каталог:** 85 категорий (загадки, космос, медицина, архитектура, шпионаж, финансы, история кино и т.д.), по 2 запроса
  на каждом языке, дальше подсказки YouTube к ним.
- **Свои темы:** «Настройки анализа» → «Автопоиск», по одной на строку, на любом языке. Идут раньше каталога.
- **Темы от Claude:** кнопка «Новые темы через Claude» (≈ $0,1). Claude смотрит каталог и лучшие найденные ниши и
  предлагает 30 новых направлений с запросами на всех языках (data/topics_claude.json).
- **Очередь подниш** хороших ниш.

Почти одинаковые запросы («ancient egypt facts» и «ancient egypt documentary») считаются одной нишей и повторно
не проверяются.

## Поиск по запросу

Вкладка «По запросу»: свои темы, по одной в строке. Галочка «перевести тему» переводит тему на язык
каждого выбранного рынка (можно писать по-русски), перевод бесплатный. Пустое поле берёт стартовые темы.

## Подниши

Подниша это отдельная ниша со своим баллом, но программа помнит, от какой ниши она пошла. Под названием подниши
написано «от: …» (клик открывает родителя), у широкой ниши написано «подниш: N». В карточке есть «Дерево подниш»:
проверенные подниши с баллами, сколько из них сильнее родителя (с них стоит заходить) и какие ждут проверки
в очереди автопоиска. Подниша, добавленная чипом из карточки и проверенная поиском по запросу, тоже запоминает родителя.

## Хранилище

Ниши с полным анализом, достаточными данными и баллом от 65 попадают в хранилище сами. Любую нишу можно
добавить кнопкой «★ В хранилище». У каждой ниши статус («Новая», «Изучаю», «Беру в работу», «Отказ»)
и заметка. Повторный анализ обновляет оценку, но статус и заметку не трогает; ниши со статусом «Отказ»
автопоиск больше не перебивает. Файл `data/vault.json`, обновления программы его не трогают.

## Куда идти

Вкладка «Куда идти» отвечает на главный вопрос: по каждому языку три лучшие темы (только полный анализ, достаточно
данных, без форматов и каши), отсортированные по итогу с учётом денег, их слабое место и лучший рабочий формат языка.
Кнопка «Стратегия по рынкам через Claude» (≈ $0,2–0,5) читает все найденные ниши и по каждому языку говорит:
идти или нет, с какой ниши начать, запасные, риск и шаги на первую неделю, плюс в каком порядке запускать рынки.

## Сравнение языков

Одна и та же тема на разных рынках. В карточке ниши кнопка «Сравнить на других языках» переводит запрос
(бесплатно) и делает полный анализ на каждом рынке: на рынки, отмеченные галочками языков, или на все остальные,
если отмечен только язык ниши. Это ≈ 244 единицы квоты на язык, повтор в течение 3 дней идёт из кэша.
Поиск по запросу с галочкой «перевести» и несколькими языками тоже собирает такую группу.

Вкладка «Сравнение языков» показывает по каждой теме таблицу: балл, вечнозелёность, просмотры/подписчики,
новые успешные каналы, долю миллионников, число роликов по теме, срок до 1000 подписчиков, RPM и доход при 1M
просмотров. Столбец «Итог с учётом денег» = балл × (0,5 + 0,5 × RPM рынка / лучший RPM в группе), по нему
рынки отсортированы. Лучшие значения выделены, строка открывает нишу.
Столбец «Критерии» показывает, где рынок отстаёт от лучшего и сколько баллов итога на этом теряет.

Цели в штуках («новых успешных каналов для максимума», «сильных малых каналов») умножаются на размер рынка
из «Настроек анализа»: EN 1, ES 0,6, DE 0,5, FR 0,5, RU 0,7. Иначе небольшой рынок проигрывал бы просто потому,
что каналов на нём меньше. Когда меняется формула оценки, программа при запуске сама пересчитывает ниши из кэша.

В хранилище каждый язык темы лежит отдельной записью со своим статусом и заметкой. Фильтр по языку
показывает только нужный рынок, галочка «только темы на нескольких языках» оставляет связанные темы.
У каждой записи видно ту же тему на других языках: «★» уже в хранилище, «+» кладёт этот язык туда же.

## Настройки анализа

Кнопка «Настройки анализа» вверху открывает все пороги и веса: длину роликов, порог успеха по каждому рынку,
что считать малым, крупным и новым каналом, страны, которые не учитываем, цели оценки (сколько «просмотры /
подписчики» и новых каналов дают максимум, когда тема считается узкой или массовой) и веса шести критериев.
Изменённые поля подсвечиваются, рядом видно значение по умолчанию. Настройки хранятся в `data/settings.json`.

После сохранения все найденные ниши пересчитываются по новым правилам бесплатно, из кэша. Если данных ниши
в кэше уже нет (поиск хранится 3 дня), у неё обновляется только итоговый балл по новым весам. Период и длины
поиска меняют сам поиск, поэтому действуют только на новые запуски.

Кнопка «Фильтры» над таблицей оставляет только ниши, которые проходят ваши условия: балл, «просмотры / подписчики»,
число новых успешных каналов, доля миллионников, вечнозелёность, сколько роликов по теме, число успешных роликов
и их длина. Так удобно искать «золотые» подниши. Фильтры запоминаются.

## Разборы через Claude

Нужен ключ Claude API (console.anthropic.com, оплачивается отдельно от подписки), он вписывается в «Ключи API».
Модель выбирается у кнопки: Opus 5.5 умнее, Sonnet 5.5 примерно вдвое дешевле. Стоимость каждого разбора видна в отчёте.

- **«Разбор ниши»** в карточке ниши. Claude получает все цифры программы, успешные ролики, каналы, теги и подсказки
  поиска и оценивает нишу по чек-листу: заработок, спрос, конкуренция, долговечность, сложность производства,
  запас идей, рост. Итог от 1 до 10, три риска, свободный угол и 15 тем для первых роликов.
- **«Разбор»** у канала в таблице каналов. Программа собирает топ-10 роликов канала по просмотрам и 10 последних
  (около 10–15 единиц квоты YouTube), обложки топ-роликов (Claude их видит) и комментарии к топ-5.
  Claude разбирает формат, формулу заголовков, превью, аудиторию, слабые места, даёт 10 идей и вердикт.
  Субтитров чужих роликов YouTube API не отдаёт, поэтому структуру ролика Claude оценивает по косвенным данным.

Отчёты хранятся в `data/reports.json` и открываются в карточке ниши.

Без Claude программа сама считает: за сколько месяцев молодые каналы ниши доходят до 1000 подписчиков,
сколько успешных роликов нужно для 4000 часов просмотра, запас идей (успешные темы и подсказки поиска)
и примерный RPM с доходом при 100K, 500K и 1M просмотров. RPM настраивается в «Настройках анализа»:
точный RPM YouTube показывает только владельцу канала.

Справа сверху счётчик расходов на Claude: всего, за текущий месяц и число разборов. Цена считается по токенам
каждого ответа и ценам модели (data/claude_spend.json). Точная сумма в console.anthropic.com.

## Как анализируется ниша

1. Поиск по каждой длительности (ролики 4–20 минут и длиннее 20 минут, по 50 штук за последние 180 дней),
   затем статистика роликов и каналов.
2. Отбрасываем ролики короче 8 минут и ролики на другом языке (по указанному языку видео, а если он
   не указан, по письменности и пометкам вроде «Hindi Documentary»).
3. Каналы из Индии, Пакистана, Бангладеш, Непала и Шри-Ланки не смотрим совсем (`EXCLUDE_COUNTRIES`),
   как и ролики на хинглише.
4. Теги успешных роликов показываются как «похожие подниши».

## Тема, формат или каша

YouTube ищет по словам, поэтому запрос не всегда даёт одну нишу. Программа проверяет, о чём ролики выдачи:
- **тема**: у большинства роликов в названии или тегах есть слова темы запроса;
- **формат**: в запросе только слова подачи («explicado en 10 minutos», «all types explained»), ролики про что угодно.
  Балл показывает, как работает сама подача. Такой формат можно применить к своей теме;
- **каша**: про тему запроса меньше половины роликов (порог в «Настройках анализа»). Балл снижается до −50%,
  такие ниши не попадают в «Лучшие» и в хранилище сами, и из них не растут подниши.

В карточке ниши блок «О чём ролики в выдаче» показывает частые слова названий. Фильтр над таблицей оставляет
только темы, форматы или кашу. Подсказки YouTube, ушедшие от темы, автопоиск больше не берёт, а у формата
и каши не показывается категория родителя.

## Оценка ниши (0–100)

| Критерий | Вес | Что считается |
|---|---|---|
| Просмотры ≫ подписчики | 30% | Медиана «просмотры / подписчики» у роликов каналов до 200K, набравших порог просмотров (0.3× → 0, 10× → максимум), и доля таких роликов |
| Новые каналы растут | 20% | Каналы, чей первый длинный ролик вышел за последние 90 дней, с роликом от порога просмотров (3 таких = максимум) |
| Мало конкурентов | 15% | Доля каналов от 1M подписчиков (0% → максимум, 40% → 0) и сколько роликов по теме вообще есть на YouTube (2K → максимум, 200K → 0) |
| Вечнозелёность | 15% | Доля успешных роликов старше 2 месяцев (их смотрят до сих пор) и мало «трендовых» слов в названиях (новости, годы, релизы) |
| Стабильный спрос | 10% | Просмотры не держатся на одном ролике, и несколько малых каналов имеют ролики ≥ 1× |
| Формат и нагрузка | 10% | Длина успешных роликов и сколько длинных роликов в неделю их каналы выкладывали за 3 месяца (≤1 в неделю = легче зайти) |

Порог просмотров: 10K для английского и русского рынков и 5K для испанского, немецкого и французского (`MIN_VIEWS_EN` и т.д.).
На русском рынке ролик без указанного языка засчитывается, если в названии есть кириллица и нет украинских букв.
Ролики ниже порога не считаются успешными: они не попадают в примеры, теги и расчёт «просмотры / подписчики».
Свежий ролик (младше 2 недель), который ещё не добрал порог, не учитывается вовсе: он просто не успел.
Свежий ролик, уже набравший порог, идёт в зачёт.

Частота загрузок и дата первого ролика берутся из последних 50 длинных роликов каждого малого канала
(до 40 каналов на нишу). Значок «≈» на дашборде значит, что узнать не удалось и частота оценена грубо.

Пометка «мало данных» означает, что в выдаче меньше 10 длинных роликов, меньше 5 роликов малых каналов
или меньше 3 роликов малых каналов с порогом просмотров.

## Квота

Каждый ключ даёт 10 000 единиц в день. Полный анализ одной ниши стоит около 244 единиц
(два поиска по 100, статистика 4 и последние ролики до 40 каналов), то есть примерно 40 ниш в день на ключ
и около 160 на четыре ключа. Разведка в автопоиске стоит около 102 единиц.
Чтобы тратить вдвое меньше, впишите в `.env` строку `SEARCH_DURATIONS=long`: тогда ищутся только ролики
длиннее 20 минут.

- Ответы API кэшируются в `data/cache/` (поиск на 3 дня), повторный анализ той же ниши бесплатен.
- Когда ключ упирается в квоту, инструмент переключается на следующий. Если закончились все,
  анализ останавливается, уже готовые результаты сохраняются.
- Расход за сегодня по каждому ключу виден на дашборде.
