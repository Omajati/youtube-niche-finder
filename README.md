# YouTube Niche Finder

Ищет перспективные ниши для длинных роликов (от 8 минут) на YouTube: где малые каналы
набирают просмотров кратно больше, чем у них подписчиков, новые каналы быстро растут,
а миллионников почти нет. Рынки: английский, испанский, немецкий, французский.

## Приложение для Mac (проще всего)

1. Скачайте [NicheFinder.zip](https://raw.githubusercontent.com/Omajati/youtube-niche-finder/main/release/NicheFinder.zip).
   Двойной щелчок распакует архив.
2. Перетащите «Поиск ниш» в папку «Программы» и запустите.
3. Первый раз Mac скажет, что не может проверить разработчика: нажмите «Готово», откройте Системные настройки →
   Конфиденциальность и безопасность и внизу нажмите «Всё равно открыть».
4. При первом запуске программа сама доустановит всё нужное (1–2 минуты) и откроет своё окно.
5. Впишите ключи YouTube API в окне «Настройки» (оно откроется само, если ключей нет).

Когда выходит новая версия, вверху появляется зелёная кнопка «Обновить». Ключи, результаты и кэш сохраняются.

Где что лежит: программа в `~/NicheFinder`, ключи и результаты в `~/NicheFinder/data`.

### Как выпустить новую версию

Поднимите число в `VERSION`, затем `bash mac/release.sh "что нового"`, закоммитьте и запушьте в `main`.

## Через GitHub Desktop (для разработки)

1. Установите [GitHub Desktop](https://desktop.github.com/) и войдите в свой аккаунт GitHub.
2. File → Clone repository → `youtube-niche-finder` → Clone. Папка появится в `Documents/GitHub`.
3. Дважды кликните `start.command` в этой папке. В первый раз создастся `.env` и откроется
   в TextEdit: впишите ключи, сохраните и снова кликните `start.command`.

Дальше просто запускайте `start.command`: он сам подтягивает свежую версию и открывает дашборд.
Если `git pull` не сработает, нажмите в GitHub Desktop кнопку **Fetch origin → Pull origin**.
Ключи (`.env`) и результаты (`data/`) при обновлении не трогаются.

Если Mac пишет, что файл от неизвестного разработчика: правый клик по `start.command` → Открыть → Открыть.

## Запуск вручную

Нужен только Python 3.9+, внешние библиотеки не требуются.

1. Скопируйте `.env.example` в `.env` и впишите ключи YouTube Data API v3 в `YOUTUBE_API_KEYS`
   (до 4 штук через запятую). Файл `.env` не попадает в git.
2. Запустите дашборд:
   ```
   python app.py
   ```
   Откроется http://localhost:8766. Слева впишите темы и языки и нажмите «Запустить анализ».

Можно и из командной строки:
```
python cli.py "unsolved mysteries" --langs en --expand 3 --max 8
python cli.py --langs es --expand 2      # автопоиск от стартовых тем
```

### Как получить ключ

Google Cloud Console → новый проект → APIs & Services → Library → «YouTube Data API v3» → Enable →
Credentials → Create credentials → API key. Повторите в каждом Google-аккаунте.

## Как ищутся ниши

1. Берём темы (ваши или стартовые для каждого языка: загадки, странные истории, забытая история…).
2. Расширяем каждую тему подсказками поиска YouTube (бесплатно, квоту не тратит).
3. Для каждой ниши: два поиска (ролики 4–20 минут и длиннее 20 минут, по 50 штук за последние 180 дней),
   затем статистика роликов и каналов.
4. Отбрасываем ролики короче 8 минут и ролики на другом языке (по указанному языку видео, а если он
   не указан, по письменности и пометкам вроде «Hindi Documentary»).
5. Теги успешных роликов показываются на дашборде как «похожие подниши»: клик добавляет тему
   в следующий запуск.

## Оценка ниши (0–100)

| Критерий | Вес | Что считается |
|---|---|---|
| Просмотры ≫ подписчики | 35% | Медиана «просмотры / подписчики» у роликов каналов до 200K, набравших порог просмотров (0.3× → 0, 10× → максимум), и доля таких роликов |
| Новые каналы растут | 25% | Каналы, чей первый длинный ролик вышел за последние 90 дней, с роликом от порога просмотров (3 таких = максимум) |
| Мало миллионников | 20% | Доля каналов от 1M подписчиков. 0% → максимум, 40% и больше → 0 |
| Стабильный спрос | 10% | Просмотры не держатся на одном ролике, и несколько малых каналов имеют ролики ≥ 1× |
| Формат и нагрузка | 10% | Длина успешных роликов и сколько длинных роликов в неделю их каналы выкладывали за 3 месяца (≤1 в неделю = легче зайти) |

Порог просмотров: 10K для английского рынка и 5K для испанского, немецкого и французского (`MIN_VIEWS_EN` и т.д.).
Ролики ниже порога не считаются успешными: они не попадают в примеры, теги и расчёт «просмотры / подписчики».
Свежий ролик (младше 2 недель), который ещё не добрал порог, не учитывается вовсе: он просто не успел.
Свежий ролик, уже набравший порог, идёт в зачёт.

Частота загрузок и дата первого ролика берутся из последних 50 длинных роликов каждого малого канала
(до 40 каналов на нишу). Значок «≈» на дашборде значит, что узнать не удалось и частота оценена грубо.

Пометка «мало данных» означает, что в выдаче меньше 10 длинных роликов, меньше 5 роликов малых каналов
или меньше 3 роликов малых каналов с порогом просмотров.

## Квота

Каждый ключ даёт 10 000 единиц в день. Анализ одной ниши стоит около 244 единиц
(два поиска по 100, статистика 4 и последние ролики до 40 каналов), то есть примерно 40 ниш в день на ключ
и около 160 на четыре ключа.
Чтобы тратить вдвое меньше, впишите в `.env` строку `SEARCH_DURATIONS=long`: тогда ищутся только ролики
длиннее 20 минут.

- Ответы API кэшируются в `data/cache/` (поиск на 3 дня), повторный анализ той же ниши бесплатен.
- Когда ключ упирается в квоту, инструмент переключается на следующий. Если закончились все,
  анализ останавливается, уже готовые результаты сохраняются.
- Расход за сегодня по каждому ключу виден на дашборде.
